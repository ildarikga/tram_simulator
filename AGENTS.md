# Локальный гид по проекту

Браузерный трамвайный симулятор Казани: JavaScript ES modules, Three.js и Vite. Интерфейс и пользовательская документация — на русском языке.

## Где искать контекст

- Перед изменением поведения прочитай соответствующий раздел [README.md](README.md): там описаны возможности и ограничения прототипа.
- `src/main.js` связывает интерфейс, управление поездкой, выбор маршрута и сохранение своих маршрутов в localStorage.
- `src/scene.js` создаёт сцену, процедурные вагоны, камеры и анимацию дверей; `src/style.css` задаёт оформление и адаптивность.
- `src/data.js` содержит параметры вагонов и исходные маршруты; `src/geography.js` подключает локальную географию; `src/osm-city.js`, `src/rail-network.js` и `src/stops.js` отвечают за город, граф рельсов и остановки.
- При работе с ассетами прочитай [public/models/README.md](public/models/README.md) и [public/data/LICENSE.md](public/data/LICENSE.md): там система координат, порядок экспорта и условия использования геоданных.

## Запуск и проверка

Нужен Node.js 22.12+ или 24+. Установи зависимости через `npm ci`; команды проекта определены в `package.json`.

- `npm run dev` запускает сервер на порту 5173.
- `npm run build` проверяет production-сборку.
- `npm test` выполняет браузерные сценарии из `tests/simulator.spec.js`. Сначала запусти dev-сервер отдельным процессом: Playwright сам его не поднимает. Нужен установленный Google Chrome; конфигурация находится в `playwright.config.js`.
- После изменения геометрии вагонов или дверей запусти `node scripts/check-models.mjs`.
- При изменениях интерфейса проверь настольный и мобильный вид; существующие браузерные тесты сохраняют снимки в `test-results/`.

Для правок документации проверь команды, пути и ссылки по исходникам. В отчёте укажи выполненные проверки и их результат.

## География и модели

- Сохраняй систему координат: X — восток, Y — вверх, Z — юг; единицы — метры, географический центр — 49.12° E, 55.79° N. Локальное направление движения вагона — +Z, правая сторона водителя — −X.
- Карта загружается из `public/data/kazan-map.geojson`. Обновление снимка через `npm run fetch-map` требует сети и перезаписывает данные; выполняй его при задаче на обновление карты.
- Для повторного экспорта GLB запусти dev-сервер и `node scripts/export-models.mjs`; скрипт требует Chrome. Меняя процедурную геометрию, учитывай, нужны ли обновлённые файлы в `public/models/`.
- Сохраняй атрибуцию OpenStreetMap и условия лицензии данных. Описывай маршруты как предварительные трассы, а процедурные вагоны как игровые заготовки, пока точность не подтверждена.
- Исходники и поставляемые данные хранятся в Git. Зависимости, сборка, npm-кеш и результаты проверок исключены через `.gitignore`.
